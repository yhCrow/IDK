# 1.1 Complexity & Limits

Before writing any code, read the constraints. They tell you which algorithm the setter expects.

## The rule of thumb

A C++ solution runs roughly **$10^8$ simple operations per second**. Multiply your complexity by the input size. If the result is under about $10^8$ per second of time limit, the solution will probably pass.

| Max $n$ | Target complexity | Typical technique |
|---|---|---|
| $n \le 10$ | $O(n!)$ | Try all permutations |
| $n \le 20$ | $O(2^n \cdot n)$ | Bitmask brute force / bitmask DP |
| $n \le 500$ | $O(n^3)$ | Floyd–Warshall, interval DP |
| $n \le 5000$ | $O(n^2)$ | 2D DP, all pairs |
| $n \le 10^5$ to $10^6$ | $O(n \log n)$ | Sorting, binary search, segment tree |
| $n \le 10^8$ | $O(n)$ | Linear scan, two pointers, prefix sums |
| $n \le 10^{18}$ | $O(\log n)$ or $O(1)$ | Maths, binary search on answer, fast power |

## Big-O in one minute

- Drop constants: $O(3n) = O(n)$.
- Keep the biggest term: $O(n^2 + n) = O(n^2)$.
- Nested loops multiply: a loop inside a loop over $n$ is $O(n^2)$.
- Halving each step gives $O(\log n)$ — binary search, fast power.

```cpp
// O(n^2): all pairs
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        check(a[i], a[j]);

// O(n log n): sort, then one pass
sort(a.begin(), a.end());
for (int i = 1; i < n; i++)
    best = min(best, a[i] - a[i - 1]);
```

## Integer overflow

| Type | Max value | Rough size |
|---|---|---|
| `int` | $2^{31} - 1 = 2\,147\,483\,647$ | $\approx 2.1 \times 10^9$ |
| `long long` | $2^{63} - 1$ | $\approx 9.2 \times 10^{18}$ |

If a **sum** or **product** can go above about $2 \times 10^9$, use `long long`. For example, $10^5$ values each up to $10^9$ sum to $10^{14}$.

```cpp
long long sum = 0;              // not int!
long long area = 1LL * w * h;   // cast BEFORE multiplying
```

## Fast input and output

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
// Use '\n' instead of endl — endl flushes the output every time.
```

> **Tip:** Getting TLE (Time Limit Exceeded) usually means the complexity is wrong, not that the code needs small speed-ups. Recheck the table above.
