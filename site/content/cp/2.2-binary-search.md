# 2.2 Binary Search

Binary search halves the search range each step, so it takes $O(\log n)$ steps. $\log_2(10^9) \approx 30$, so even huge ranges are fast.

## Searching a sorted array

Use the standard library — it is correct and fast.

| Call | Returns |
|---|---|
| `lower_bound(a.begin(), a.end(), x)` | Iterator to the first element $\ge x$ |
| `upper_bound(a.begin(), a.end(), x)` | Iterator to the first element $> x$ |
| `upper_bound(...) - lower_bound(...)` | How many elements equal $x$ |
| `binary_search(a.begin(), a.end(), x)` | `true` if $x$ is present |

```cpp
vector<int> a = {1, 3, 3, 3, 7};
int i = lower_bound(a.begin(), a.end(), 3) - a.begin();   // 1
int j = upper_bound(a.begin(), a.end(), 3) - a.begin();   // 4
int cnt = j - i;                                          // 3 copies of 3
```

The array **must be sorted** first.

## Binary search on the answer

Many "find the minimum X such that…" problems can be turned into a yes/no question:

> *Is X enough?* — `check(X)`

If `check` is **monotonic** (false, false, …, false, true, true, …), binary search finds the first `true`.

```cpp
// Find the smallest x in [lo, hi] with check(x) == true.
long long lo = 0, hi = 2e9;
while (lo < hi) {
    long long mid = lo + (hi - lo) / 2;
    if (check(mid)) hi = mid;      // mid works, try smaller
    else lo = mid + 1;             // mid fails, go bigger
}
// lo is the answer
```

For "find the **largest** x with `check(x)` true", round the midpoint **up** so the loop cannot get stuck:

```cpp
while (lo < hi) {
    long long mid = lo + (hi - lo + 1) / 2;
    if (check(mid)) lo = mid;
    else hi = mid - 1;
}
```

## Common mistakes

1. **Infinite loop** — using `lo = mid` with a midpoint rounded down.
2. **Overflow** — `(lo + hi) / 2` can overflow `int`; use `lo + (hi - lo) / 2` or `long long`.
3. **Wrong bounds** — make sure the true answer is inside `[lo, hi]` at the start.
4. **Non-monotonic check** — binary search only works if the answer switches from false to true exactly once.
